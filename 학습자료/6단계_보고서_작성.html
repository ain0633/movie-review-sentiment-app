1보고서 구조의 논리

9개 섹션이 "무엇을 → 어떻게 → 왜 → 한계" 순서로 흐르게 배치했습니다.

읽는 이의 피로를 줄이는 장치: ① 문단은 3~4문장 이내 ② 나열은 전부 표로 ③ 수치는 본문이 아니라 표에, 본문엔 해석만 ④ 같은 말 반복 없이 각 섹션이 새 정보 하나씩. "길게 쓴 보고서"가 아니라 "빨리 읽히는 보고서"가 잘 쓴 보고서입니다.

2AI 티가 나지 않는 문체 — 무엇을 뺐나

AI 티 나는 패턴보고서에서의 처리
"~해보겠습니다", "살펴보도록 하겠습니다"기술 보고서 표준 문어체(-다/-했다)로 통일. 반말이 아니라 논문·기술문서의 중립 문체
이모지, 느낌표, 과한 강조(**볼드 남발**)전부 제거. 강조는 표의 음영 셀 하나로
"놀랍게도", "흥미롭게도" 같은 감탄 전환"예상과 다른 결과가 나왔다"처럼 사실 서술로
대칭적 3연속 나열 ("첫째… 둘째… 셋째…")문장 길이를 불규칙하게, 나열은 표로 이동
근거 없는 일반론 ("최근 AI 기술의 발전으로…")모든 주장 뒤에 실측 수치 (27.6ms, 488MB, 16/16…)
사람이 쓴 보고서처럼 읽히는 결정적 요소는 문체보다 구체성입니다. "빠릅니다"가 아니라 "P99 39.5ms", "가볍습니다"가 아니라 "488MB". 실측값은 흉내낼 수 없는 서명 같은 것이라, 수치가 촘촘한 글은 자연히 사람의 작업 기록으로 읽힙니다.

3남은 작업 — 캡처 4장

보고서 안의 빨간 점선 박스 4개를 캡처로 교체하면 끝납니다. Cloud Run 데이터가 살아있을 때 찍고, 비어 있으면 재시드(BACKEND_URL=... python scripts/seed_db.py) 후 찍습니다.

  1. FastAPI Docs — …run.app/docs, 엔드포인트 전부 보이게 (필수 제출물)
  2. 영화 목록 — 배포 앱, 주소창 포함
  3. 리뷰 등록 — 감성 결과 표시된 순간
  4. 최근 리뷰 — 10건 목록

HTML에 그림 넣기: 캡처를 학습자료 옆에 저장하고 점선 박스 자리를 <img src="파일명.png" style="width:100%">로 바꾸면 됩니다. 그 후 Ctrl+P → PDF.

PDF 변환을 워드가 아니라 HTML 인쇄로 하는 이유: 구조도·ERD가 텍스트 다이어그램이라 이미지 깨짐이 없고, 페이지 나눔(page-break)을 CSS로 제어할 수 있어 표가 중간에 잘리지 않습니다.

4셀프 체크

Q1. 벤치마크에서 INT8이 더 느렸는데도 보고서에 그대로 쓴 이유는?

불리한 실측을 숨기지 않고 "총비용 기준 의사결정"으로 연결하면 오히려 판단력의 증거가 된다. 결과를 각색한 보고서는 질문 두 개면 무너진다.

Q2. 한계 섹션이 감점 요인이 아니라 가점 요인인 이유는?

한계를 원인·개선 방향과 함께 쓰면 "몰라서 못 한 것"과 "알고 미룬 것"이 구분된다. 시스템의 경계를 아는 것이 엔지니어링 역량의 핵심 신호다.

Q3. 재현 방법 섹션을 넣은 이유는?

"돌려볼 수 있는 제출물"은 신뢰 비용을 없앤다. 채점자가 명령 몇 줄로 모든 주장(테스트 통과, 시드, 벤치마크)을 직접 검증할 수 있다.
